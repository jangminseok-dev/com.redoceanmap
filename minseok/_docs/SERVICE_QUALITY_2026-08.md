### 1-1. 점수 의미론 왜곡 — "주의" 등급 상권을 사실 반전으로 강력 추천 ★최우선

- **증상(p04 실측)**: 답변 "성수역을 강력히 추천합니다. 유동인구 성장률이 서울 평균을 크게
  상회 (47.9점)". 원데이터(`/market/trdar/{성수역}/score`): 유동인구 성장 value **-0.11%**
  (벤치마크 +0.72% **미달**), 컴포넌트 점수 47.9(50=서울 평균 미달), **총점 44.9 '주의' 등급**.
- **원인**: LLM이 "점수 50=서울 평균" 의미론을 모른 채 숫자를 자유 서술. phase2 컨텍스트에
  점수의 해석(등급·평균 대비 방향)이 결정론 문장으로 없다.
- **수정**:
  - `chat_interactor`의 상권 컨텍스트에 컴포넌트별 해석을 **코드가 문장으로** 넣는다:
    "유동인구 성장 47.9점(서울 평균 50 **미달**, 실측 -0.11% vs 서울 +0.72%)" 형식.
  - **등급 결정론 가드**: 총점 등급이 '주의'/'위험'인 상권에는 "추천"·"강력히" 어휘를
    후처리로 차단하고, 등급을 답변 첫 문단에 코드로 삽입한다(eval_scorer에 금지 패턴 추가).
- **검증**: p04 재실행 — "주의 등급" 명시 + 추천 어휘 부재. 채점기 회귀 테스트.

### 1-4. 상권 매칭 실패 = 422 원문 노출 + '목동' 커버리지 (m4·p01·p06)

- **증상(실측 3건)**: ① "유동인구 많고 폐업률 낮은 상권 3곳"(지역명 없음) → 62초 뒤
  `{"detail":"유효한 상권을 찾지 못했습니다."}` ② "서울에서 어디가 안전한지"(광역 질문) → 동일 422
  ③ **"목동에서 반찬가게"** — 실재 지역인데 422(86초). 양천구 목동 상권 매칭 실패는 원인 조사 필요
  (`_mentioned_codes` 어간 매칭이 '목동'을 못 잡는지, 상권명에 '목동'이 없는지 실데이터 확인).
- **수정**:
  - **422를 사용자에게 그대로 내지 않는다**: `NoValidAreaError`를 200 안내 응답으로 변환 —
    "지역 이름(동/역/거리)을 함께 물어봐 주세요. 예: 강남역 카페" + 조건 질의면 랭킹 안내.
  - **조건 질의 라우팅(I-14 확장)**: "폐업률 낮은/유동인구 많은 N곳" 패턴을 감지하면 LLM 대신
    기존 `/market/areas/ranking`(폐업률·유동인구 필터 보유)을 호출해 결정론으로 N곳을 채운다.
  - 목동 원인에 따라 별칭 보강(행정동 축은 I-3으로 이미 있음 — `adm_dong` 매칭 경로 연결 검토).
- **검증**: m4·p01·p06 재실행 — 3건 모두 200 + 유용한 응답. 라우터 테스트.

### 1-5. 서술 텍스트 품질 버그 3종 (소형·일괄)

1. **`None` 노출**: `operatingMonthsText` = "…(지역 평균 **None**개월)" — narrator에서 결측 시
   해당 구를 생략. (m1 실측)
2. **숫자 포매팅**: "지지선인 **1,245,729.86원**"(q10) — 원화는 정수 반올림, 달러는 소수 2자리
   상한. 컨텍스트 조립부에 포맷 함수 일원화.
3. **forecast 인사이트 주어 누락**: position insight "…60일 저점보다 +35.8% 위에 있습니다.
   RSI 49(중립 구간). **하루 평균 변동폭(6.4%)의 5배입니다.**" — 무엇의 5배인지 없음.
   `forecast_narrator`의 position 문장을 "지지선까지 여력은 하루 평균 변동폭의 5배입니다"로 명시.
4. **카드-페이지 모순 표기**: 채팅 카드 `monthlyRevenueText`="매출 데이터 없음"인데 같은 상권
   점수 페이지는 월매출 366억 표시(m1 실측 — 카드는 업종별, 페이지는 상권 전체).
   카드 문구를 "**카페 업종** 매출 데이터 없음(상권 전체 매출은 상세에서)"로 축을 명시.
- **검증**: narrator·컨텍스트 단위 테스트 + m1·q10 재실행.
