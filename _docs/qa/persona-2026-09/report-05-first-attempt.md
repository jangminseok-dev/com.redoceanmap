# P05 정우진(미국주식 데이터 트레이더) — 1차 시도: 회원가입 429로 ABANDON

## 여정 로그
| # | 행동 | 본 것 | 초 | 마찰 |
|---|---|---|---|---|
| 1~6 | 가입 27회 재시도(3분, 5~20초 간격) | 매번 `요청이 너무 잦습니다. 잠시 후 다시 시도해 주세요.` | 190 | 대기 시간·원인(IP? 계정? 장애?) 구분 불가 |
| 5 | 로그인으로 확인 | FAILED — 계정 생성된 적 없음 | 1 | "이미 가입됨"과 "요청 과다"가 같은 문구 |

## 지표
```json
{"task_success": false, "steps": 6, "optimal_steps": 9, "time_to_first_meaningful_action_s": null, "friction_count": 6,
 "heuristic_violations": ["9 오류 복구: 대기 시간 없음", "1 가시성: 원인 구분 불가", "5 오류 예방: 가입 리밋(IP당 1시간 5회)이 정상 흐름을 막음"], "abandoned": true, "chat_asks": 0}
```

## 막힌 지점
`/auth/register` 429. 원인은 병렬 QA 5세션이 같은 IP로 가입해 IP당 1시간 5회 리밋에 걸린 것(실측: redis `ratelimit:register` TTL 49분). **2차 단독 재실행** 예정. 문구 지적은 유효.

## 개선 제안 3개
1. 429에 `Retry-After`·본문 대기 초 명시.
2. 가입 리밋 임계 재검토(가족·회사 같은 공유 IP는 1시간 5명이 현실적으로 막힐 수 있다).
3. "이미 존재하는 계정"과 "요청 과다" 문구·코드 분리.

## 한 줄 결론
RSI 값 하나 보려다가 회원가입 버튼이랑 3분 씨름하는 서비스는 안 쓴다.
