## 확정된 결함

### 1. 서울시 추정매출 `당월_매출_금액`은 분기 합계다 (앱 전체 3배 과장)

- 근거 ① 서울 열린데이터광장 OA-15572 FAQ 원문: **"분기당 매출 금액**은 개인 매출액과 법인 매출액의 합산값으로 …" — 포털 스스로 이 값을 분기당 매출이라 부른다.
- 근거 ② 수서역 분식 2개 점포에 "월" 38,448건이면 점포당 하루 640건, 분기로 보면 213건.
- 근거 ③ 서울 781개 상권 분식 점포당 중앙값 2,325만원 → ÷3 = 775만원/월. 통계청 분식 업종 연매출(1억 초반)과 일치.
- 근거 ④ 같은 데이터셋의 유동인구는 이미 코드가 "분기 총 ÷ 91일"로 다룬다(`footTrafficText`). 매출만 월로 읽는 것이 내부 불일치다.
- 영향 범위: chat `_format_stats`(점포당 월평균·업종 월 총매출) · 상권 상세 `SalesTrendChart` "월 매출(추정)" · 랭킹 `sales_per_store` · 입지 적합도 "점포당 월매출" · `area_stats` `monthly_sales`. 종합점수·백테스트·QoQ는 비율이라 무관.
- 수정안: DTO/ORM 이름은 두되 **표기 계층에서 ÷3 + "월 환산(분기÷3)" 명시**, 또는 라벨을 "분기 매출"로. 전자를 권장(사용자가 월 단위로 묻는다).

### 2. 소표본 점포당 값이 결론·1순위로 승격된다

- 점포 2~4개 업종은 카드 매출에 점포 집계 밖 가게가 섞여 점포당 값이 튄다. 폐업률 0%(0개)도 의미 없음.
- 수정안: `store_count < 5`면 `monthlyRevenueText`에 "(표본 N개, 참고만)" 부기, `_market_verdict_line`·`_superlative_pick` 후보에서 제외.

### 3. LLM 서술의 전망·평가 문구 (권유 인접)

- "안정적인 수익성", "빠르게 회수 가능", "빠른 매출 성장이 예상", "장기적인 성공 가능성" — 유사투자자문 미신고 원칙과 충돌하는 방향.
- 수정안: `answer_guard`에 전망 어휘 패턴(회수|성장이 예상|성공 가능성|수익성을 보여|기대할 수) 문장 제거 가드. 상권 프롬프트에도 금지 목록 추가.

### 4. 업종 미지정 상권 질문의 폐업률·점포 수

- "강남역 폐업률"처럼 업종이 없으면 범용 행이 비어 "데이터 없음"으로 답한다. store 테이블 합계로 상권 전체 개·폐업률을 낼 수 있다.
- 수정안: `AreaRawStat`에 업종 합계 폴백(전 업종 sum) 추가, `revenueSourceText`에 "전 업종 합계" 명시.
