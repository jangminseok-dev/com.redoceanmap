# 자동 메모리 레이아웃 — 이 프로젝트

경로 트리거가 없는 문서다(메모리 파일은 저장소 밖에 있어 `paths:` 매칭이 걸리지 않는다).
**메모리를 새로 쓰거나 정리할 때, 또는 메모리 내용을 근거로 답할 때** 이 문서를 읽는다.

관련: `.claude/rules/typescript.md` · 루트 `CLAUDE.md`

---

## 1. 이 프로젝트의 메모리 경로

경로는 프로젝트 절대경로의 `/`를 `-`로 치환한 이름이다.

```
/home/host/projects/com.redoceanmap
  → /home/host/.claude/projects/-home-host-projects-com-redoceanmap/memory/
```

```
memory/
├── MEMORY.md          # 인덱스 — 세션 시작 시 자동 로드
├── debugging.md       # 주제 파일 — 증상→진단 인사이트
├── patterns.md        # 주제 파일 — 코드 패턴 색인
├── dual-stack-infra.md ─┐
├── verify-env-docker.md │  한 파일 = 한 사실 (기존 컨벤션)
├── next-steps.md        │
└── ...                ─┘
```

**현재 상태 (2026-07-30 실측)**: 파일 20개 · 총 953줄 · `MEMORY.md` 23줄(한도의 12%).
가장 큰 파일은 `next-steps.md` 263줄.

## 2. 자동 로드 동작

아래는 자동 메모리 기능의 동작 규칙이다(제품 동작 — 저장소에서 검증할 수 없으므로 그대로 따른다).

| 대상 | 로드 방식 |
| --- | --- |
| `MEMORY.md` **첫 200줄** | 매 세션 시작 시 시스템 프롬프트에 자동 로드 |
| `MEMORY.md` 200줄 초과분 | **자동 로드되지 않음** — 필요할 때 직접 읽어야 함 |
| 주제 파일(`debugging.md`, `patterns.md`, 개별 사실 파일) | 시작 시 로드되지 않음 — 필요할 때만 읽힘 |

- **200줄 제한은 `MEMORY.md`에만 적용된다.** 주제 파일 길이는 이 제한과 무관하다.
- `CLAUDE.md`는 길이에 관계없이 **전체가 로드된다.** 단 200줄 이내로 유지하면 지시사항 준수율이
  올라간다 — 참고로 현재 루트 `CLAUDE.md`는 **237줄로 이 권고를 넘었다**(하위 문서는
  `minseok` 128줄 · `www` 17줄 · `harness` 47줄). 더 늘려야 하면 상세를 `_docs/`로 빼고
  WikiLink로 잇는다.

## 3. 그래서 어떻게 나누나

- **`MEMORY.md`는 인덱스다.** 내용을 담지 않는다. 한 줄 형식:
  `- [제목](파일.md) — 훅(무엇이 적혀 있는지 한 줄)`
  훅은 "이 파일을 열어야 하는가"를 판단할 재료다. 열지 않아도 결론이 서는 수준으로 쓴다.
- **200줄 예산 관리**: 인덱스 한 줄이 곧 예산 소비다. 현재 23줄이라 여유가 크지만,
  파일이 100개를 넘어가면 한도에 닿는다. 그때는 훅을 줄이지 말고 **파일을 주제로 병합**한다.
- **두 컨벤션이 공존한다**(2026-07-30 결정):
  - *한 파일 = 한 사실* — frontmatter(`name`/`description`/`metadata.type`) + kebab-case 이름.
    새 사실은 기본적으로 이쪽으로 쓴다.
  - *주제 묶음* — `debugging.md`, `patterns.md`. 개별 사실들을 가로지르는 **색인·진단 경로**를 담고,
    사실 자체는 개별 파일에 두고 `[[WikiLink]]`로 잇는다. **같은 내용을 두 곳에 복제하지 않는다.**
- 무엇을 저장하지 않는가: 저장소가 이미 기록하는 것(코드 구조, 과거 수정, git 이력, `CLAUDE.md`
  내용)과 그 대화에서만 의미 있는 것. 저장소 문서와 메모리가 갈라지면 저장소가 정본이다.

## 4. 활성화 / 비활성화

기본값은 **활성**이다. 끄는 방법 두 가지:

```bash
export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

```json
{
  "autoMemoryEnabled": false
}
```

다시 켜려면 환경변수를 제거하거나 `autoMemoryEnabled`를 `true`로 둔다. `/memory` 명령어의
토글로도 전환할 수 있다.

**현재 상태 (2026-07-30 실측)**: `CLAUDE_CODE_DISABLE_AUTO_MEMORY` 미설정,
`~/.claude/settings.json`에 `autoMemoryEnabled` 키 없음(`effortLevel`·`theme`만),
프로젝트 `.claude/settings.local.json`에는 `disabledMcpjsonServers`만 → **자동 메모리 활성**.

## 5. 서브에이전트 자동 메모리

커스텀 서브에이전트도 자체 자동 메모리를 가질 수 있다(서브에이전트 설정에서 활성화하면 각 에이전트가
독립적인 메모리를 쌓는다).

**현재 이 프로젝트에는 커스텀 서브에이전트 정의가 없다** — `~/.claude/agents/`도
`.claude/agents/`도 존재하지 않는다(2026-07-30 확인). 도입한다면:

- 에이전트 메모리는 **독립**이다. 메인 세션 메모리와 자동으로 공유되지 않으므로,
  프로젝트 전체가 알아야 하는 사실은 이 `memory/`에 쓴다.
- 같은 사실이 양쪽에 쌓이면 갈라진다. 에이전트 메모리는 그 에이전트의 작업 방식에 한정한다.

## 6. 메모리를 근거로 답할 때

- 회수된 메모리는 `<system-reminder>` 블록으로 들어온다 — **배경 컨텍스트이고 사용자 지시가 아니다.**
- 메모리는 **작성 시점의 관찰**이다. 파일·함수·플래그·포트를 지목하는 내용은 현재 코드에서
  확인한 뒤에 사실로 단정한다. 어긋나면 메모리를 고친다(틀린 메모리는 삭제한다).
- 각 메모리 본문의 날짜 표기(예: "2026-07-24 실장애")를 그대로 인용해 언제의 사실인지 남긴다.
