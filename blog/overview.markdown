## 2. 프로젝트 목적

> "이 동네에 카페를 차려도 괜찮을까?"
> "오늘 이 종목 뉴스, 주가에 의미가 있는 건가?"

이런 질문에 **감이 아니라 데이터로** 답하는 것이 목적이다. 지금은 상권 통계·시세·뉴스·공시를
각각 다른 곳에서 찾아 스스로 종합해야 한다.

- 공공데이터(상권·인허가·실거래가)와 시세·재무·뉴스 데이터를 정규화해 쌓고,
- 로컬 LLM이 실데이터를 근거로 해설하는 대화 인터페이스로 제공한다.
- 목표는 단계적이다: ① 개인 투자/분석 도구 → ② 운영·품질 기반 완성 → ③ 실사용자 서비스.
- 제약: 개발 단계 비용 0원(무료 리소스만) · 온프레미스 운영 · 사업자 등록·행정 신고 없이 가능한 범위만
  (유사투자자문업 미신고 → 어떤 화면에서도 매수·매도 권유 표현을 쓰지 않는다).

</div>

## 4. 기대 효과

- **흩어진 데이터의 통합 해석** — 상권·주식·뉴스·공시를 각각 찾아다니는 대신,
  한 대화창에서 실데이터 근거와 함께 묻고 답을 받는다.
- **비용 0원 운영 구조** — 로컬 LLM + 무료 공공 API만으로 수집→분석→해설 전 구간이 돌아간다.
- **측정 기반 개선 사이클** — 답변·검색 품질을 골든셋 지표로 고정해, 개선이 "느낌"이 아니라
  숫자로 확인된다. 기각된 실험도 근거 문서로 남는다.

## 5. 기술 스택 및 아키텍처

| 계층 | 스택 |
| --- | --- |
| 백엔드 | Python 3.13 · FastAPI · SQLAlchemy 2.0(asyncio) · Pydantic 2 · Alembic |
| 프론트엔드 | Next.js 16 · React 19 · TypeScript 5 · Tailwind 4 |
| 데이터 | PostgreSQL(pgvector) · Redis · Neo4j(그래프 투영만, 질의 도입은 보류) |
| 운영 | k3s 단일 노드(백엔드·인증·CronJob) + 도커 컴포즈(DB 계층) · Cloudflare Tunnel · Vercel(프론트) |
| LLM | EXAONE 7.8B 로컬 추론(Ollama) — 단일 모델 정책, 임베딩은 bge-m3 |

- **모듈러 모놀리식** — 앱 내부는 헥사고날/클린(`adapter → app → domain`),
  앱 사이는 스타 토폴로지(허브 + 스포크). 두 구조 모두 import-linter 계약 5종으로 정적 강제.
- 인증은 별도 프로세스로 분리 — JWT 개인키를 백엔드 본체가 보유하지 않는 경계 설계.

## 6. 왜 이 스택인가

**왜 MSA가 아니라 모듈러 모놀리식인가**

1인 개발에서 MSA는 운영 비용만 늘린다. 대신 앱 사이 경계를 import-linter 계약으로
**정적 강제**해, "모놀리식인데 구조가 무너지지 않는" 상태를 유지한다.
구조 위반은 리뷰가 아니라 도구가 잡는다.

**왜 로컬 LLM인가**

- 비용 0원 제약 — 유료 API 없이 수집→분석→해설 전 구간이 돌아야 한다.
- 데이터가 외부로 나가지 않는다 — 대화·프로파일이 서드파티 API에 전송되지 않는다.
- 소형 모델(7.8B)의 한계는 인정하고, 프롬프트 규칙 + 평가 하네스 회귀 게이트로 관리한다.

**왜 단일 모델 정책인가**

모델이 여러 개면 품질 문제의 원인 추적과 비교 기준이 흐려진다. 추론 모델은 하나로 고정하고,
교체는 환경 변수 스위치 + **134문항 평가 하네스 회귀 대조**를 통과할 때만 한다.

## 7. 데이터 수집 및 연계

| 데이터 | 출처 | 주기 |
| --- | --- | --- |
| 상권 분기 데이터 (매출·유동인구·점포 등) | 서울 열린데이터광장 | 분기 — 신규 분기 자동 적재 |
| 가맹 브랜드 창업비용(가맹금·교육비·보증금) | 공정거래위원회 · 공공데이터포털 | 월 1회 |
| 한국 종목명·코드 | KRX KIND 상장법인 목록 | 조회 시 캐시 |
| 인허가 (개폐업 선행 신호) | 행정안전부 LOCALDATA | 배치 |
| 상업용 부동산 실거래가 | 국토교통부 | 월간 |
| 시세·재무제표 | yfinance | 일간 |
| 종목·상권 뉴스 (+bge-m3 임베딩) | Google News RSS | 일간 |
| 공시 원문 (청킹 실험) | DART | 실험 단위 |

- 수집은 전부 **독립 배치 스크립트** — 서비스 런타임과 분리되어 실패해도 서비스에 영향이 없다.
- 전 출처가 무료 공공/공개 API다. 약관 리스크가 있는 스크래핑(지도 리뷰·SNS)과 사업자 서류가 필요한 유료·기관 데이터는 배제했다.

## 8. 보안 및 개인정보 보호

- **토큰 발급 경계 분리** — JWT 개인키는 별도 인증 프로세스만 보유. 백엔드 본체는
  공개키 검증만 가능해, 본체가 침해되어도 토큰을 위조할 수 없다.
- **공개 접점 방어** — HTTPS + IP 기반 rate limit. 무차별 로그인 시도 차단을 실측으로 검증했다.
- **권한 관리** — 어드민은 RBAC(역할-권한 테이블)로 엔드포인트 단위 가드,
  가드 누락은 접근 매트릭스 테스트가 잡는다.
- **개인정보 최소 수집** — 프로파일은 정확 금액 대신 밴드(구간)만 받는다.
  마이데이터·신용점수 연동은 로드맵에서 제외했다.
- **백업 3계층** — 일간 로컬 + 주간 오프사이트 미러 + 분기 복원 리허설(실복원 검증).

## 9. 아키텍처 규율

- 스포크끼리 직접 import 금지 — 교차 협력은 허브 포트 경유, 허브는 스포크를 모른다.
- 앱 전용 DB와 공유 DB를 섞지 않는다.
- 스켈레톤(빈 껍데기) 코드 금지 — 실사용하지 않는 추상을 만들지 않는다.
- 과설계 명시 배제 — [명시적 비추천 목록]({{ '/roadmap/' | relative_url }}#rejected)으로 관리.

## 10. 품질 관리 및 테스트

- pytest 기반 테스트 (유스케이스는 스텁 포트로 검증), 구조 위반은 import-linter가 잡는다.
- LLM 답변 품질은 **평가 하네스**로 관리 — 골든셋 + 결정론 채점기 + baseline 회귀 게이트.
- 검색(RAG) 품질도 별도 트랙으로 계측 — recall@k·nDCG 지표와 사람 라벨링
  (LLM이 자기 검색을 심판하는 순환은 금지).
- **기각도 결과로 쓴다** — 게이트 미달 실험은 폐기하지 않고 기각 근거를 문서로 남긴다.

**목표 문장**

> "검색 품질을 골든셋 nDCG@5로 고정하고 회귀 게이트를 걸었습니다. 하이브리드 검색은
> 게이트(+0.03)를 넘으면 채택하고, 못 넘으면 기각한 근거를 남깁니다."

개선 주장이 "느낌"이 아니라 이 문장처럼 숫자로 성립하는 상태를 유지한다.

## 11. 답변 책임 원칙

- 투자 지시·확률 단정 금지 — 데이터 근거만 제시하고 판단은 사용자에게 남긴다.
- 표본 기준 미달 통계는 확률 주장에 쓰지 않는다 (참고 정보로만).
- 개인화는 서술 관점 조정까지 — 프로파일 근거 매매 권유는 프롬프트 규칙으로 금지.
- **결론은 코드가 쓴다** — 상권 답의 첫 줄(어느 상권을 먼저 볼지)과 비교표·예산 후보는 LLM이 아니라 결정론 코드가 만들고, LLM은 그 아래 해설만 붙인다. 근거 없는 숫자는 답변 가드가 지운다.
- AI 모의투자는 "어느 계정이 무엇을 샀다"는 기록까지만 보여 준다 — 따라 하라는 문장은 어디에도 없다.
